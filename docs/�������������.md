# 0.5 界面与真结局设计

核查与实现日期：2026-10-03。

## 界面参考

- [Claude Cowork 官方产品页](https://claude.com/product/cowork)：对话是主要工作入口，相关内容与操作状态围绕当前任务组织。本项目借鉴主次层级，保留固定输入区、轻量上下文与明确的连接入口。
- [Manus My Computer 官方介绍](https://manus.im/blog/manus-my-computer-desktop)：本机文件入口和授权操作紧密相连。本项目将文件选择、确认、回收放在一个页面，给出清晰的完成结果。
- [Microsoft Copilot Actions 官方介绍](https://blogs.windows.com/windows-insider/2025/11/17/copilot-on-windows-copilot-actions-begins-rolling-out-to-windows-insiders/)：在输入区选择任务方式，并可查看操作进度。本项目借鉴就近展示屏幕共享状态和操作反馈的方式。

以上仅用于信息层级与交互参考，不表示本项目具备这些产品的全部自动执行能力。艾希当前可对话、记录待办、经确认回收文件，并在授权后分析桌面截图。

## 保留的画风

暗红黑色背景、暖灰正文、低饱和青色状态、编号导航、细边框、少量等宽字与轻扫描线。减少重复装饰和高密度说明，给对话与操作结果留出空间。CRT 风格体现在界面，日常表达保持自然。

对话空状态给出三个真实可用的交流方向；任务与文件各有明确空状态；设置按对话、感知、陪伴、外观声音分组并可快速跳转；保存按钮与未保存状态固定在表单底部。共同记忆只呈现可查看、修正和删除的内容，不在日常页面暴露原始人格提示词或开发原理。

## 真结局依据

[TapTap 玩家整理的结局文本](https://www.taptap.cn/moment/153303884167645551)与[另一位玩家记录的结局片段](https://www.taptap.cn/review/40311245)在主要表达上相互印证；[游戏官方商店页](https://store.steampowered.com/app/553640/ICEY/?l=schinese)确认了挑战旁白、区分玩家与角色的 Meta 叙事。结局文字来自社区记录，并非官方逐字剧本发布，提示词采用含义改写，不转载整段台词。

提炼为五个稳定内核：珍惜陪伴、坦率感谢、认识自身边界、通过经历形成自我、祝愿彼此找到道路并期待重逢。由此把旧版偏冷的“初次接触操作者”调整为有自主判断、温和而不依附的桌面伙伴。

“在桌面重逢”以及具体日常表达属于本项目延伸，不声称是官方后续剧情。不能默认用户已通关、就是昔日玩家或与艾希存在恋爱关系。角色中关于看见与联系的表达，不会覆盖实际屏幕权限；没有本次截图时仍不得声称看到了桌面。

完整运行提示词：`src/prompts/icey-persona.md`。技术说明与原作出处保留在文档，不进入日常页面。
